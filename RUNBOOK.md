# RUNBOOK: agent mode (Claude Code + Google Flow)

The prompt is `docs/agent-prompt.md`. One run at a time, one browser = one agent. CLI: `powershell -NoProfile -ExecutionPolicy Bypass -File src/agent.ps1 <command> -Run <run> [-Item <id>] [-File <path>]`; every command prints one JSON line `{ok,...}`; `ok:false` carries `error` (read it, do not guess).

1. `prepare`: snapshots the queue (URLs, product photos, review photos) into the run; lists the items.
2. Per item: look at the product photo(s) yourself; `context-brief` shows what to write; write the JSON; `context -File <json>`. No web access for the product (AGENTS.md section 1-2).
Sessions: several app windows can run at once (own queue, runs, logs and port each, one source); `start-app.cmd <name>` opens one, `PR_SESSION` / `PR_WORKSPACE` name it for CLI runs. See AGENTS.md "Phiên".
3. Images in Google Flow (Playwright MCP: the person's everyday Chrome profile chosen in the app, extension mode, the person clicks Connect and your tabs sit in a group named Product Review; or the tool's own Chrome `workspace/chrome-profile` when the app says so):
   1. `flow-brief` for every item: gives `aspect`, `uploads` (review photo first, product photo second) and `condensed_prompt`.
   2. `browser_tabs`: browser up? One tab. A Google sign-in page = STOP (`CAUSE:LOGIN`). Open https://flow.google.com, new project, Images (Hình ảnh), aspect from `aspect`, x1.
   3. BATCH: per item upload the 2 `uploads` in that order as references, paste `condensed_prompt` in the BOTTOM prompt box (not the project name), submit. HUMAN PACING (Flow flags bursts as "unusual activity"): run `node core/flow-pace.mjs gate --tag <item id>` right BEFORE every prompt you submit; it waits the human-like time itself (5-12 s between prompts, 20-45 s after a group of 3-4, max 8 per 2 minutes); submit right after it returns; never several prompts behind one gate, never skip it. After each group wait for its results, download and register them, then go on with the next group.
   4. Per group: wait for its results, then download each original 1K image and register it before the next group. DOWNLOADS (the Downloads folder is shared by every window of this machine): around EACH download run `node core/flow-pace.mjs download-lock acquire --tag <item id>` (blocks until no other window is downloading), click download, move the NEW file at once into your own session folder (`workspace/tmp/flow-downloads/` of this session, renamed `<item id>.<ext>`), check it is the right picture (expected size, the prompt tile you submitted), then `download-lock release --tag <item id>`; never take a file you did not just download.
   5. `register-image -Item <id> -From <png>` per image (`-From`, not `-File`; `flow-brief` prints the exact command). Before registering, look at the image: an item with a SIGN WORDING line in its `condensed_prompt` must show exactly that wording; sample lettering or other text left on the sign = do not register, write `[CAUSE:SIGN_TEXT]` for the item. An item that already has an image is never run again.
4. Per item: `review-brief` (prints `prompt_file`, rating, name, image) → read `prompt_file`, write the review to a .txt file → `write-review -File <txt>` (1st failure returns `{ok:false,problems,final:false}`: fix once; 2nd failure = `REVIEW_QUALITY`, exit 1) → `finish` (uploads to the results store, adds stars/name/date; `RESULT_CONFIG` or `RESULT_UPLOAD` = item NOT done; success = status `awaiting_user_review`). The agent never touches review.json.
5. `run-summary` (prints `{ok,run,items:[{id,url,status,image,cause?}],awaiting_user_review,errors,unfinished}`), then STOP and report in Vietnamese: image paths, items waiting for approval, errors. The person approves in the app (Duyệt & xuất file).

Browser rules: `await page.bringToFront();` first in every browser_run_code_unsafe; one tab; no waitForFunction; a call over 30 s is stuck.
Errors: `[CAUSE:LOGIN|QUOTA|REFUSED|BROWSER] text` per item; no endless retry.
Never: Giữ/Bỏ, Loox export, sending anything, watermark removal via Flow, rerunning an item that has an image, signing in for the person.
Review-only run (UI Kiểu chạy = Chỉ viết review, `run-images.ps1 -ReviewOnly`): no image, no results-repo upload; reviews are written from each item's attached original review photo (an item without one fails clearly, others continue). Review-only rows show in Duyệt with the original review photo and export to Loox with an empty photo column. Agent mode (Claude + Flow) always makes images, so it is not offered for review-only.

Note: agent mode above is a separate path. The app's Viết review box can also pick Claude (`core/ai/providers/claude.ps1`, `claude -p`, Read-only, no MCP, no Chrome); it needs only the Claude CLI signed in (`PR_CLAUDE_CLI` or PATH).

## Quét web (scan mode: Claude Code + a shop website)

The prompt is `docs/scan-prompt.md` (the Quét web popup's Bắt đầu quét runs it through the same runner as agent mode, `core/setup/agent-run.mjs` mode `scan`; one agent run at a time, one browser = one agent). CLI: `powershell -NoProfile -ExecutionPolicy Bypass -File src/scan.ps1 <command> -Project <id> ...` (`-Scan` is the old name of `-Project`); every command prints one JSON line `{ok,...}`. Claude finds the menu and the products itself in the tool's OWN Chrome (Playwright MCP, no sign-in); the CLI only writes files into the web's project folder `workspace/projects/<id>/` (see "Dự án" below; older scans in `workspace/scans/` still get `used` updates).

1. `start -Site <home page> -Max <n> -Run <run>`: finds the project of that site (id = host, `dreamyvows.com` = `dreamyvows-com`) or creates it with an empty `products.csv` (header `product_url,product_image,review_images,sign_text,title,collection,used,reviews_count,reviews_checked_at`); prints the project id and how many products it already has. Then `known` lists the links already there: Claude skips them, so Max counts NEW products only.
2. Browser first (`browser_tabs`, one tab, open the site; a login wall, captcha or block page = STOP).
3. Read the main menu: product categories only (no About, Blog, policies, cart, account).
4. Per category: collect up to Max products (link, title, category, URL of the MAIN image), write a JSON array `{url,title,collection,collection_url,image_url}`, `add-many -File <json>` (or `add -Url -Title -Collection -ImageUrl|-ImageFile`). The CLI downloads and checks each image (real JPG/PNG; WebP/AVIF is re-asked as JPG with `format=jpg`; still not an image = `NEEDS_PNG`: screenshot the image element to a .png and `add -ImageFile`), skips links the project already has (`duplicate`: the row, its `used` and its review number stay) and stops a category at Max NEW products of this scan (`collection_full`). New rows start with `used = F`. Nothing is ever deleted by a scan.
5. `finish`: rows, per category, `missing_images`, `merge` (added / already_known / not_seen_this_scan) and `menu.json` with the product count of each category; then Claude reports in Vietnamese and stops.

After the scan: Nhập hàng loạt reads `products.csv` as is (Chọn file…, or "Nhập vào danh sách" in the popup). Rows with `used = T` are skipped ("bỏ qua N dòng đã dùng"); `title` and `collection` are notes. `review_images` and `sign_text` stay empty: the person chooses the review photos and the lettering. A link that finishes (Codex checkpoint, agent `finish`) sets its row to `used = T` in every scan table (`Set-ScanUsed`, `src/application/scan-store.ps1`).

## Dự án (one project per web: scan once, then only update)

Every shop is a project in `workspace/projects/<id>/`: `project.json` (id, name, site, created, updated, last_scan, last_reviews_check, max_per_collection), `menu.json` (categories with link and product count), `products.csv` (the Nhập hàng loạt table: `product_url,product_image,review_images,sign_text,title,collection,used,reviews_count,reviews_checked_at`), `images/`, `reviews.json` (the last number seen per link: count, rating, source, checked_at) and `session.json` (the running scan). The "Dự án" popup (button next to Quét web) lists the projects and shows the products of the selected one (filter by category and "Chỉ chưa dùng", used T/F toggle, review number and its date). Buttons: Quét cập nhật (the Quét web run on the project's own link: only new products are added, `used` and review numbers are kept, nothing is deleted), Cập nhật số review, Nhập vào danh sách (the used = F rows go through Nhập hàng loạt, `reviews_count` / `reviews_checked_at` are ignored on import), Mở thư mục. The Quét web popup can pick an existing project.

Thêm vào hàng chờ (button on the bottom row of the popup; the boxes "Số sản phẩm" (default 10) and "Ảnh ngữ cảnh / sản phẩm" sit in the status area above it): for the SELECTED project, takes that many products (respecting the popup's category filter and "Chỉ chưa dùng", skipping links already queued) and prepares them for image creation: the link into `workspace/urls.txt`, the project's product photo as the product image and N scene photos per product (box "Ảnh ngữ cảnh / sản phẩm", 1-4, default 2) into `workspace/reference-inputs/references.json` (entries[] -> product_url, products[] -> file + sha256 + scenes[] -> file + sha256, copies under `workspace/reference-inputs/<project>-scenes/`). Scenes box = 0 skips Claude: `/api/project/queue/direct` (`scan.ps1 queue-direct`) queues the first N products of the table (same order and filters, links already queued skipped) with only the link and the project photo. It does NOT start image creation and writes no review text/author/rating. Prompt `docs/queue-prompt.md` (mode `queue`, `/api/project/queue/run|status|stop`): Claude looks at the product photo, picks N different scenes that fit from the right library group ("Áo" apparel, "Thể thao ngoài trời" jerseys/fishing/running/cycling, "Nội thất" furniture), reports a product with no fitting scene instead of forcing one, and works to the last product. CLI (`src/scan.ps1`): `queue-todo` (products to queue), `scenes` (library groups / photos with category), `scene-get` (downloads one library photo, md5 checked, prints its path and used_count), `queue-add -Url -Group -SceneNames a,b[,c,d]` (1-4 different photos) (verifies sha256, writes the entry and the urls.txt line; never changes an existing entry or link). Scene checks use a perceptual hash (16x16 dHash, `src/infrastructure/image-phash.ps1`, cache `workspace/source-photos/phash.json`; same picture re-saved/resized = distance 0-6 of 256, different photos 99+, limit 20): `scenes -Group g [-Category c] [-Prefetch]` adds `used_count` (queue + last 5 runs), `dup_of` (first visually identical library photo) and `checked` per photo and lists unused photos first in a stable shuffled order; `queue-add` rejects `[CAUSE:SCENE_DUPLICATE]` (two scenes of one product look the same) and `[CAUSE:SCENE_REUSED]` (a scene already used by another product in the queue or the last 5 runs; `-AllowReuse` overrides). The prompt tells Claude: never reuse a scene across products of a batch, skip dup_of / used_count > 0, look at 6+ candidates, spread the picks; the report ends with "X distinct scenes / Y scene slots". When the run ends the main window list reloads so the result can be checked (Xem / sửa).

### Chuẩn bị trước (prep mode) and the instant queue

The popup has two SEPARATE groups, each with its own numbers (remembered per session in `config/run-settings.json`: `queueCount`, `queueScenes`, `prepCount`, `prepScenes`): Thêm vào hàng chờ (Số sản phẩm 1-200, default 10; Ảnh ngữ cảnh / sản phẩm 1-4, default 2) and Chuẩn bị trước (Số sản phẩm, 0 = all remaining, default 50; Ảnh ngữ cảnh / sản phẩm, default 4 so the queue can take any 1-4 from the same rows). The footer line says how many prepared rows the queue can use with its scene number: `Chuẩn bị trước: X sẵn sàng (≥ S ảnh) · Y chưa chuẩn bị · Z đã ở hàng chờ` (`prep-status -SceneCount S` -> `ready_usable`).

Picking scenes at queue time is slow, so it can be done IN ADVANCE: "Chuẩn bị trước" (button next to Thêm vào hàng chờ in the popup; `POST /api/project/prep/run`, `docs/prep-prompt.md`, runner mode `prep`) lets Claude go through the products of the selected project (category / "Chỉ chưa dùng" filters) that are not prepared yet and store S different fitting scenes per product in `workspace/projects/<id>/prepared.csv` (columns `product_url,group,scenes,scene_sha256,scene_count,prepared_at,status,consumed_at,consumed_by`; status `ready` | `skipped:no-fit` | `consumed`; shared by every session; one row per product the moment it is picked, written under a file lock). It never touches `urls.txt` / `references.json`. The prep and queue runs use the LIGHT runner (own state `workspace/runs/prep-run.json`, own Dừng, no browser and no Chrome profile) and may run while Bắt đầu runs; two light runs at once are refused.

1. `prep-status` (counts) and `prep-todo -Limit 30` (products not queued and not prepared; call again after every 30).
2. Library: `scenes`, `scenes -Group ... -Prefetch -Limit 30`, `scene-get` (same as the queue prompt; used_count also counts prepared scenes).
3. Per product: Read the product photo, look at >= 6 candidates, pick S different fitting scenes (no duplicate look, no reuse across products).
4. `prep-add -Url <link> -Group "<group>" -SceneNames "a,b" -SceneCount S` right after each pick (or `-Skip -Reason "no-fit: ..."`); ALREADY_PREPARED / ALREADY_QUEUED skip; SCENE_DUPLICATE / SCENE_REUSED pick other scenes. Keep working until everything is prepared or the number in OPTIONS is reached.
5. `prep-status`, then report in Vietnamese and stop.

`Thêm vào hàng chờ` first runs `queue-from-prepared -Project <id> -Limit N [-SceneCount S] [-Collection] [-UnusedOnly]` WITHOUT an agent: it queues up to N ready rows (re-validating that the scene files exist, sha256 matches and the scenes are not used by another product; a row that no longer validates is dropped back to "not prepared"; a queued row becomes `consumed`). Only for the shortfall M does the Claude queue run start ("lấy N từ kho đã chuẩn bị, M cần Claude chọn thêm"). The queue writes (`Add-QueueEntry`, `Save-ManualMapEntry`, `Remove-FromQueue`) go through one OS mutex per session workspace (`Use-QueueMutex`), so a running batch, the app and queue-from-prepared never lose each other's entry. New CLI: `prep-todo`, `prep-add`, `prep-status`, `queue-from-prepared`.

CLI (`src/scan.ps1`, one JSON line each): `projects`; `project -Project <id>` (summary + menu); `set-used -Project <id> -Url <u> -Used T|F`; `known` / `set-menu -File <json>` (scan helpers); `reviews-todo -Project <id> [-Limit n]` (links to read, never checked first); `set-reviews -Project <id> -Url <u> -Count <n> [-Rating <x>] [-Source <where>]` (stores the number Claude reports and the time; unknown link = error). A link that finishes sets its row to `used = T` in every project table (`Set-ScanUsed`).

### Cập nhật số review (reviews mode, READ ONLY)

The prompt is `docs/reviews-count-prompt.md` (runner mode `reviews`, `POST /api/project/reviews/run` {project}, `GET /api/project/reviews/status`, `POST /api/project/reviews/stop`; one agent run at a time, shared with Flow and Quét web). No code finds or parses review numbers: Claude opens each link in the tool's OWN Chrome, reads the number the page itself shows (whatever widget or wording shows it) and records it with `set-reviews`.

1. `reviews-todo` lists the links (never checked first).
2. Browser first (`browser_tabs`, one tab; no Playwright MCP = STOP).
3. Per link: open it, dismiss a cookie banner with one click, read the review number on the page (scroll if it helps; "No reviews yet" = 0; no review information anywhere, or a number that is not clearly this product's = do not guess, note the link for the report and go on to the next link; one doubtful link never stops the run).
4. `set-reviews -Url <link> -Count <n> [-Rating <x>] [-Source "<where>"]`; a failed call is retried once. Keep working until every link is done: a headless run ends the moment Claude writes a message without a tool call, so no progress message, partial report or question before the last link (a 2026-11-18 run stopped after 4 of 346 links because the prompt asked for a progress line).
5. `project` shows what is stored; Claude reports in Vietnamese and stops.

STOP IF a login wall, captcha or block page. NEVER write, submit, edit, delete or vote on a review, fill a form, sign in, guess a number or set a target; the project stores only the observed count (no target, no "missing" number).
