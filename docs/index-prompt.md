# Index prompt (optional tool: Claude Code tags the scene photo library; no step of Chuẩn bị trước or Thêm vào hàng chờ needs it, and it has no button in the Dự án popup)

The only source of this prompt: the app ("Gắn nhãn kho ảnh" in the Dự án popup) and `buildPrompt({ mode: "index" })` in `core/setup/agent-run.mjs` read the `text` block below. Placeholders: `{{TOOL}}` = this tool's folder, `{{RUN}}` = the run id, `{{OPTIONS}}` = this run's options (library group, how many photos). Same fixed template as `docs/prep-prompt.md` and `docs/queue-prompt.md`: TASK, OPTIONS, TOOL, STEPS (numbered, 1:1 with "Gắn nhãn kho ảnh" in the "Dự án" section of RUNBOOK.md), STOP IF, NEVER.

It runs on the LIGHT runner (no browser, no Playwright MCP, no Chrome profile), so it can run while Bắt đầu runs. It writes ONLY the shared library index `workspace/source-photos/scene-index.json` through `src/scan.ps1 scene-index-add` (validated, under a file lock). Claude writes the tags after looking at each photo ONCE on a numbered contact sheet; the CLI computes sha256 / perceptual hash, records visual copies (dup_of) and never tags anything by itself. The index is reused by every project and session; later runs only tag new or changed photos.

```text
TASK: Product Review — tag the scene photo library once (setting, people, light, wall space, product types it fits) so scene picking looks at few images; no project, no queue, no image creation — agent: Claude Code
RUN: {{RUN}}
OPTIONS: {{OPTIONS}}
TOOL: {{TOOL}}
SHARD (only when OPTIONS contains "shard:"; otherwise ignore this line): other runs tag the same library at the same time, each on its OWN slice. Add `-Shard <k/n>` to EVERY scene-index-todo call and tag only the photos it lists.
STEPS (follow RUNBOOK.md "Dự án" > "Gắn nhãn kho ảnh", in order, do not skip; every command prints one JSON line {ok,...}; CLI = powershell -NoProfile -ExecutionPolicy Bypass -File src/scan.ps1 <command> ...):
1. Setup: cd {{TOOL}}; read AGENTS.md (sections 0, 5 and "Dự án") + RUNBOOK.md "Dự án". OPTIONS gives the library group (empty = every group) and how many photos to tag (all = until nothing is left). CLI scene-index-status: photos and indexed per group. Work on the groups with indexed < photos, the group of OPTIONS only when it names one.
2. Next batch: CLI scene-index-todo -Group "<group>" -Limit 20: the next untagged photos (downloaded, visual copies already recorded as dup_of and left out) and `sheet` = ONE png with a big number on each photo, `photos` = number -> name. `count` 0 = this group is done, go to the next group.
3. Look ONCE: Read the sheet (one Read for the whole batch; open a single photo with scene-get + Read only when a tile is really unclear). For EVERY number write one JSON item: {"group":"<group>","name":"<name from the legend>","setting":"<one short English place: bedroom, kids room, nursery, living room, dining room, kitchen, office, bar counter, cafe, cafe window, restaurant, shop, wedding backdrop, party, studio, outdoor, garden, street, sports field, gym, other>","people":"yes|no","light":"day|night|warm","wall_space":"yes|no" (a clear free wall area where a wall sign or frame could hang),"fits":["the product types this scene could show naturally, e.g. neon wall sign, wall art, coffee table, dining chair, polo shirt, hoodie, fishing shirt, jersey, mug"],"note":"<= 15 words: what is in the picture"}. A photo no product could use (blurry, a close-up with no setting, text over it, collage) = "usable":"no" with fits []. Be honest: tags only from what you SEE.
4. Store it NOW: write the items (a JSON array) with the Write tool next to the sheet (same folder, name "<sheet name>.tags.json") and CLI scene-index-add -File <json>. `errors` lists the items that were not stored (fix them and send ONLY those again, once). Then go back to step 2 until the number in OPTIONS is reached or every group is done. This run ends the moment you write a message without a tool call, so write NO progress message, NO partial report and NO question before the end; the only message you write is the step 5 report.
5. Finish: CLI scene-index-status, then STOP. Tell me in Vietnamese: how many photos were tagged per group, how many were marked not usable, the errors, and the status numbers (indexed / photos).
STOP IF: the library cannot be reached (network) after 1 retry: stop and report; a sheet that cannot be read twice. Do NOT retry endlessly (at most 1 retry of a stuck step); still run step 5.
NEVER: edit scene-index.json, prepared.csv, urls.txt, references.json or any project file by hand (only the CLI writes them); put anything into the queue or prepare products; start image creation or press Bắt đầu; open a browser or any web page; tag a photo you did not look at; copy tags from one photo to another without looking; write a script that tags photos for you.
```
