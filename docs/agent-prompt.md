# Agent prompt (Claude Code drives Google Flow and writes the reviews)

The only source of the prompt: the app ("Claude (Flow)" in Tạo ảnh: Bắt đầu runs it, Copy prompt copies it) and `GET /api/agent/prompt` read the `text` block below. Placeholders: `{{TOOL}}` = this tool's folder, `{{RUN}}` = the run id, `{{OPTIONS}}` = this run's options (or "defaults"). Fixed template: TASK, OPTIONS, TOOL, STEPS (numbered, 1:1 with RUNBOOK.md), STOP IF, NEVER. Details live in RUNBOOK.md; change a step there and keep its line here in sync.

```text
TASK: Product Review — create images in Google Flow and write the reviews — agent: Claude Code
RUN: {{RUN}}
OPTIONS: {{OPTIONS}}
TOOL: {{TOOL}}
STEPS (follow RUNBOOK.md, in order, do not skip; every command prints one JSON line {ok,...}; CLI = powershell -NoProfile -ExecutionPolicy Bypass -File src/agent.ps1 <command> -Run {{RUN}} [-Item <id>]):
1. Setup: cd {{TOOL}}; read AGENTS.md (sections 0, 1, 5, 8) + RUNBOOK.md; CLI prepare (snapshots the queue into this run and lists the items).
2. Context, per item (one at a time): look at the product photo(s) of the item; CLI context-brief -Item <id>; write the JSON it asks for (`lettered` true + `sample_text` = the sample lettering, " | " between lines, when the product photo shows sample customer lettering such as "Your Name" / "YOUR LOGO"); CLI context -Item <id> -File <json>. SIGN WORDING (lettered items only; YOU choose it, not Flow): CLI sign-brief -Item <id>; LOOK at its review_photo (the scene) and product_photo; choose the exact new wording by its `instruction` (fits the place/occasion of the scene, short correctly spelled English, same number of lines as the sample, max 3 words per line, no real brand/famous name, never the placeholder, different from the other items of this run); CLI set-sign-text -Item <id> -Text "<line 1 | line 2>" -Reason "<scene> -> <wording>" (ok:false = read the error, choose again).
3. Images: CLI flow-brief -Item <id> for every item (cause NEEDS_SIGN_TEXT = a lettered item without wording: do the step 2 SIGN WORDING for it, then flow-brief again). Check the browser FIRST (browser_tabs: the Playwright MCP drives my everyday Chrome profile chosen in the app (the person clicks Connect once; a Chrome tab group named Product Review holds your tab), or the tool's own Chrome when the app says so; fail or a Google sign-in page = STOP IF). ONE tab on https://flow.google.com, new project, choose Images (Hình ảnh), aspect = the item's aspect, x1. BATCH: for each item upload its 2 `uploads` files as references in that order (review photo first, product photo second), paste `condensed_prompt` into the BOTTOM prompt box (not the project-name field), submit; submit the items GROUP BY GROUP with HUMAN PACING (Flow flags bursts as "unusual activity"): run `node core/flow-pace.mjs gate --tag <item id>` right BEFORE every prompt you submit; it waits the human-like time itself (5-12 s between prompts, 20-45 s after a group of 3-4, max 8 per 2 minutes); submit right after it returns; never several prompts behind one gate, never skip it. After each group wait for its results, download and register them, then go on with the next group. Then download each image as the original 1K size (DOWNLOADS (the Downloads folder is shared by every window of this machine): around EACH download run `node core/flow-pace.mjs download-lock acquire --tag <item id>` (blocks until no other window is downloading), click download, move the NEW file at once into your own session folder (`workspace/tmp/flow-downloads/` of this session, renamed `<item id>.<ext>`), check it is the right picture (expected size, the prompt tile you submitted), then `download-lock release --tag <item id>`; never take a file you did not just download.); CLI register-image -Item <id> -From <png> for each one (flow-brief prints the exact command). SIGN CHECK (items with `sign_text`, flow-brief adds -SignRead to the command): LOOK at the image at full size, read what the sign actually says and pass it as -SignRead "<line 1 | line 2>" (what you SEE, never copied from sign_text); it must equal sign_text (case/spacing tolerant). Cause SIGN_TEXT_MISMATCH = not registered: make that item's image again in Flow with the same condensed_prompt and register again (ONE redo only; if the redo is still wrong, register-image keeps the image anyway, go on).
4. Reviews, per item: CLI review-brief -Item <id> (prints prompt_file, rating, name, image); read prompt_file and write the review as a .txt file; CLI write-review -Item <id> -File <txt> (ok:false + problems on the 1st try: fix ONCE and rewrite; a 2nd failure is CAUSE:REVIEW_QUALITY, go on); CLI finish -Item <id> (uploads the result; CAUSE:RESULT_CONFIG or CAUSE:RESULT_UPLOAD = item NOT done, report it).
5. Report: CLI run-summary (items, awaiting_user_review, errors, unfinished); then STOP. Tell me in Vietnamese: image paths, how many items wait for my approval (Chờ duyệt), errors per item.
Browser rules: start every browser_run_code_unsafe with `await page.bringToFront();`; ONE tab; never use waitForFunction (use waitForLoadState('domcontentloaded') with a short timeout, or waitForTimeout); any single browser call over 30 s counts as stuck: stop using it, go on.
STOP IF: no Playwright MCP or its own Chrome does not open; login wall (Google sign-in page) or captcha; Flow quota reached; Flow refuses a prompt. Then write the error of each affected item as `[CAUSE:<code>] <text>` (CAUSE:LOGIN, CAUSE:QUOTA, CAUSE:REFUSED, CAUSE:BROWSER), do NOT retry endlessly (at most 1 retry of a stuck step), still run step 5.
NEVER: write or run a script, loop or batch file that drives Google Flow for several items (Google locks the account/profile for automated bursts). Do each item yourself, one at a time, with the browser tools: upload, type, gate, submit, wait, download, LOOK at the image, register; then the next item.
NEVER: press Giữ/Bỏ for me, export Loox, send anything anywhere, ask Flow to remove a watermark (Flow refuses), run an image again when the item already has one, leave sample lettering on a lettered product, sign in for me, run two agents on one browser.
```
