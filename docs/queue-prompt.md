# Queue prompt (Claude Code puts a project's products into the run queue, with their scene photos chosen from the library)

The only source of this prompt: the app ("Thêm vào hàng chờ" in the Dự án popup) and `buildPrompt({ mode: "queue" })` in `core/setup/agent-run.mjs` read the `text` block below. Placeholders: `{{TOOL}}` = this tool's folder, `{{RUN}}` = the run id, `{{PROJECT}}` = the project id (folder under `workspace/projects/`), `{{OPTIONS}}` = this run's options (category, only-unused, how many). Same fixed template as `docs/prep-prompt.md`, `docs/index-prompt.md`, `docs/agent-prompt.md`, `docs/scan-prompt.md` and `docs/reviews-count-prompt.md`: TASK, OPTIONS, TOOL, STEPS (numbered, 1:1 with the "Dự án" section of RUNBOOK.md), STOP IF, NEVER.

It only PREPARES the queue: no browser, no image creation, no review text. Claude looks at the photos and chooses the scenes itself (no matching code); `src/scan.ps1 queue-todo -Grouped -Sheet | scene-index-status | scene-index-todo | scene-index-add | scene-candidates | contact-sheet | scenes | scene-get | queue-add` only list, tile photos into numbered contact sheets, rank indexed scenes by their tags, download, verify (md5 / sha256) and write the entry in the format of the app's own entries. Speed: one product sheet per group of products and one candidate sheet per 20 scenes instead of one Read per photo (same as `docs/prep-prompt.md`).

```text
TASK: Product Review — put the products of a project into the run queue with N scene photos each (N from OPTIONS; prepare only, do not create images) — agent: Claude Code
RUN: {{RUN}}
PROJECT: {{PROJECT}}
OPTIONS: {{OPTIONS}}
TOOL: {{TOOL}}
STEPS (follow RUNBOOK.md "Dự án", in order, do not skip; every command prints one JSON line {ok,...}; CLI = powershell -NoProfile -ExecutionPolicy Bypass -File src/scan.ps1 <command> -Project {{PROJECT}} ...). SPEED: you look at photos on numbered CONTACT SHEETS (one Read = up to 20 photos), never one scene file at a time:
1. Setup: cd {{TOOL}}; read AGENTS.md (sections 0, 5 and "Dự án") + RUNBOOK.md "Dự án". OPTIONS gives the category (empty = all), only-unused (T/F) and how many products and "scenes per product" (S, 1-4). TOP-UPS FIRST: CLI queue-todo -TopUp -SceneCount S [-Collection "<category>"] [-UnusedOnly] lists products already prepared with FEWER than S scenes (their group, scenes and missing): for each, keep its listed scenes and pick only the missing ones from scene-candidates -Group "<its group>" (same rules as step 3), then queue-add with ALL of them in -SceneNames (the listed ones first) and -SceneCount S; they count towards N. Then CLI queue-todo -Grouped -Sheet [-Collection "<category>"] [-UnusedOnly] -Limit M with M = N + 10 (N = the products to queue from OPTIONS; the 10 extra are spares): the candidate products in order, also GROUPED by kind (groups[]: key, products with n / url / title / image, sheet = ONE contact sheet of the group's product photos numbered like n); products already in the queue are not listed. The TARGET is exactly N products queued, not M. Nothing to do = go to step 5.
2. Library index: CLI scene-index-status. If the library group you need has untagged photos (indexed < photos), tag the photos you need first like RUNBOOK "Gắn nhãn kho ảnh" (scene-index-todo -Group "<group>" -Limit 20 -> Read its sheet ONCE -> tags JSON next to it -> scene-index-add -File <json>). Groups: "Áo" apparel (shirts, polos, tees, hoodies, jackets), "Thể thao ngoài trời" jerseys / fishing / running / cycling / outdoor sports wear, "Nội thất" furniture, "Trang trí nhà cửa" home decor (wall signs, neon signs, wall art); CLI scenes lists every group.
3. Per GROUP of products, in the order of queue-todo: Read the group's product sheet ONCE and decide the product type (a product that is clearly another kind: Read its own photo and treat it alone). CLI scene-candidates -Group "<library group>" -Fits "<product type>" [-Setting "<a>,<b>"] -Limit L with L = S x (products of the group you still need) + 8 (max 60): unused, non-duplicate indexed scenes ranked by tag match, with numbered sheets (20 per sheet, numbers continue). Read EVERY sheet of the list (one Read each) and judge the fit yourself: the person / room must make sense for the product (a fishing shirt on someone outdoors, not in a studio shot of a dress). Tags only narrow the list: never pick a scene you have not seen on a sheet. Assign S DIFFERENT fitting scenes to each product, spread across the sheet (different rooms), NEVER one scene for two products of the batch (the CLI rejects SCENE_DUPLICATE / SCENE_REUSED anyway). The S scenes of one product all come from ONE library group. If you cannot find S scenes that really fit, do NOT force a bad one: leave the product out, note it for your report and GO ON.
4. Queue it as you go (right after you assigned its scenes): CLI queue-add -Url <the link exactly as listed> -Group "<group>" -SceneNames "<a>,<b>,..." -SceneCount S (exactly S names from the legend) (links the product into urls.txt and references.json with its project photo and the S scenes; verified by sha256; the picks are also recorded in prepared.csv as consumed, so the stock stays coherent). A failed call: read the error, fix your choice or retry ONCE; ALREADY_QUEUED = skip that product and say so; SCENE_DUPLICATE / SCENE_REUSED = take another scene from a sheet you already looked at (never add -AllowReuse on your own); sheets used up = scene-candidates again. KEEP WORKING until EXACTLY N products are queued (or the candidate list is used up): when a product is left out (no scene fits) or is ALREADY_QUEUED, take the NEXT product of the list instead, so the queue grows by N and never by N-1. Never queue more than N. This run ends the moment you write a message without a tool call, so write NO progress message, NO partial report and NO question before the Nth product is queued (or the list is used up); the only message you write is the step 5 report.
5. Finish: STOP. Tell me in Vietnamese: how many products were queued, each product with its S scenes (names) in one line, the products left out because no scene fit (and why), the errors, how many contact sheets you read, and last "X distinct scenes / Y scene slots" (X = different scenes used, Y = products x S; X must equal Y).
STOP IF: no products to queue (say so); the library cannot be reached (network) after 1 retry: stop and report; a scene or product photo that cannot be read. Do NOT retry endlessly (at most 1 retry of a stuck step); still run step 5.
NEVER: start image creation or press Bắt đầu; write any review text, author or rating; open a browser or any web page; edit references.json, urls.txt, products.csv, scene-index.json or any project file by hand (only the CLI writes them); change or delete an entry or link already in the queue; change `used`; reuse one scene photo twice for the same product or across products of the batch (or pass -AllowReuse); pick a scene that does not fit the product just to finish, or one you know only from its tags; write a script that matches scenes to products for you; run two agents on one browser.
```
