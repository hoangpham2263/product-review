# Queue prompt (Claude Code puts a project's products into the run queue, with their scene photos chosen from the library)

The only source of this prompt: the app ("Thêm vào hàng chờ" in the Dự án popup) and `buildPrompt({ mode: "queue" })` in `core/setup/agent-run.mjs` read the `text` block below. Placeholders: `{{TOOL}}` = this tool's folder, `{{RUN}}` = the run id, `{{PROJECT}}` = the project id (folder under `workspace/projects/`), `{{OPTIONS}}` = this run's options (category, only-unused, how many). Same fixed template as `docs/agent-prompt.md`, `docs/scan-prompt.md` and `docs/reviews-count-prompt.md`: TASK, OPTIONS, TOOL, STEPS (numbered, 1:1 with the "Dự án" section of RUNBOOK.md), STOP IF, NEVER.

It only PREPARES the queue: no browser, no image creation, no review text. Claude looks at the photos and chooses the scenes itself (no matching code); `src/scan.ps1 queue-todo | scenes | scene-get | queue-add` only list, download, verify (md5 / sha256) and write the entry in the format of the app's own entries.

```text
TASK: Product Review — put the products of a project into the run queue with N scene photos each (N from OPTIONS; prepare only, do not create images) — agent: Claude Code
RUN: {{RUN}}
PROJECT: {{PROJECT}}
OPTIONS: {{OPTIONS}}
TOOL: {{TOOL}}
STEPS (follow RUNBOOK.md "Dự án", in order, do not skip; every command prints one JSON line {ok,...}; CLI = powershell -NoProfile -ExecutionPolicy Bypass -File src/scan.ps1 <command> -Project {{PROJECT}} ...):
1. Setup: cd {{TOOL}}; read AGENTS.md (sections 0, 5 and "Dự án") + RUNBOOK.md "Dự án". OPTIONS gives the category (empty = all), only-unused (T/F) and how many products and "scenes per product" (S, 1-4). TOP-UPS FIRST: CLI queue-todo -TopUp -SceneCount S [-Collection "<category>"] [-UnusedOnly] lists products already prepared with FEWER than S scenes (their `group`, `scenes` and `missing`): for each, keep its listed scenes and pick only the `missing` ones (same rules as step 3), then queue-add with ALL of them in -SceneNames (the listed ones first) and -SceneCount S; they count towards N. Then CLI queue-todo [-Collection "<category>"] [-UnusedOnly] -Limit M with M = N + 10 (N = the products to queue from OPTIONS; the 10 extra are spares): the candidate products in order (url, title, collection, image = the project's product photo); products already in the queue are not listed. The TARGET is exactly N products queued, not M. Nothing to do = go to step 5.
2. Library: CLI scenes (the groups), then CLI scenes -Group "<group>" -Category <category> -Prefetch -Limit 30 (its photos with name, category, used_count, dup_of, checked; -Prefetch downloads the category so every photo can be compared; the list is already ordered: not used first, copies last, shuffled, so do NOT just take the first ones). Groups: "Áo" for apparel (shirts, polos, tees, hoodies, jackets), "Thể thao ngoài trời" for jerseys, fishing, running, cycling, outdoor sports wear, "Nội thất" for furniture. A photo is on disk when `local` is set; otherwise CLI scene-get -Group "<group>" -SceneNames "<name>" downloads it and prints its path. You LOOK at photos with the Read tool (the product photo, the scene photos).
3. Per product, one at a time, in the order of queue-todo: Read the product photo FIRST and decide what it is (type, how it is worn or used). Choose the right group for that type, look at candidate scene photos (scene-get, then Read) and pick S DIFFERENT scenes that fit the product: the person / room must make sense for it (a fishing shirt on someone outdoors, not in a studio shot of a dress). Never the same scene twice for one product (two different photos, not the same picture under two names), and NEVER reuse a scene across products in this batch: skip photos with dup_of set or used_count > 0 (the CLI rejects them anyway: SCENE_DUPLICATE, SCENE_REUSED). Look at at least 6 candidates per product and spread the picks across the category (different rooms, not the first fitting ones). If you cannot find S scenes that really fit, do NOT force a bad one: leave the product out, note it for your report and GO ON.
4. Queue it: CLI queue-add -Url <the link exactly as listed> -Group "<group>" -SceneNames "<a>,<b>,..." -SceneCount S (exactly S names) (links the product into urls.txt and references.json with its project photo and the S scenes; verified by sha256; the picks are also recorded in prepared.csv as consumed, so the stock stays coherent). A failed call: read the error, fix your choice or retry ONCE; ALREADY_QUEUED = skip that product and say so; SCENE_DUPLICATE / SCENE_REUSED = pick other scenes (never add -AllowReuse on your own). KEEP WORKING until EXACTLY N products are queued (or the candidate list is used up): when a product is left out (no scene fits) or is ALREADY_QUEUED, take the NEXT product of the list instead, so the queue grows by N and never by N-1. Never queue more than N. This run ends the moment you write a message without a tool call, so write NO progress message, NO partial report and NO question before the Nth product is queued (or the list is used up); the only message you write is the step 5 report.
5. Finish: STOP. Tell me in Vietnamese: how many products were queued, each product with its S scenes (names) in one line, the products left out because no scene fit (and why), the errors, and last "X distinct scenes / Y scene slots" (X = different scenes used, Y = products x S; X must equal Y).
STOP IF: no products to queue (say so); the library cannot be reached (network) after 1 retry: stop and report; a scene or product photo that cannot be read. Do NOT retry endlessly (at most 1 retry of a stuck step); still run step 5.
NEVER: start image creation or press Bắt đầu; write any review text, author or rating; open a browser or any web page; edit references.json, urls.txt, products.csv or any project file by hand (only the CLI writes them); change or delete an entry or link already in the queue; change `used`; reuse one scene photo twice for the same product or across products of the batch (or pass -AllowReuse); pick a scene that does not fit the product just to finish; write a script that matches scenes to products for you; run two agents on one browser.
```
