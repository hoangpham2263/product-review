# Queue prompt (Claude Code puts a project's products into the run queue, with their scene photos chosen from the library)

The only source of this prompt: the app ("Thêm vào hàng chờ" in the Dự án popup, option "Bốc ngẫu nhiên, không AI" off) and `buildPrompt({ mode: "queue" })` in `core/setup/agent-run.mjs` read the `text` block below. Placeholders: `{{TOOL}}` = this tool's folder, `{{RUN}}` = the run id, `{{PROJECT}}` = the project id (folder under `workspace/projects/`), `{{OPTIONS}}` = this run's options (category, only-unused, how many). Same fixed template as `docs/prep-prompt.md`: TASK, OPTIONS, TOOL, STEPS, STOP IF, NEVER.

It only PREPARES the queue: no browser, no image creation, no review text. The code draws a random sample of unused photos from the product's library group (`scene-candidates`) and tiles it into numbered contact sheets; Claude looks at the sheet and picks the scenes that fit (no matching code); `queue-add-many` records all picks of a batch with one call (sha256, not-a-copy and not-used-by-another-product checks, used-scene ledger). The same photo is never offered or picked twice, in any run or window.

```text
TASK: Product Review — put the products of a project into the run queue with S scene photos each (S and N from OPTIONS; prepare only, do not create images) — agent: Claude Code
RUN: {{RUN}}
PROJECT: {{PROJECT}}
OPTIONS: {{OPTIONS}}
TOOL: {{TOOL}}
SHARD (only when OPTIONS contains "shard file:" / "shard:"; otherwise ignore this line): other runs work on the same project at the same time, each on its OWN slice. Add `-OnlyFile <that shard file>` to EVERY queue-todo call and queue ONLY products queue-todo lists. A photo that is rejected as SCENE_REUSED may just have been taken by another run: take another one.
STEPS (every command prints one JSON line {ok,...}; CLI = powershell -NoProfile -ExecutionPolicy Bypass -File src/scan.ps1 <command> -Project {{PROJECT}} ...). FAST: batch commands in one shell call, look at photos only on numbered CONTACT SHEETS (one Read = up to 20 photos), never one file at a time, never wait or schedule anything:
1. Setup: cd {{TOOL}}; read AGENTS.md (sections 0, 5 and "Dự án"). OPTIONS gives the category (empty = all), only-unused (T/F), N (products) and S (scenes per product, 1-4). Then CLI queue-todo -Grouped -Sheet [-Collection "<category>"] [-UnusedOnly] -Limit M with M = N + 10 (the 10 extra are spares): the products in order, grouped by kind (groups[]: key, products with n / url / title / image, sheet = ONE contact sheet of the group's product photos numbered like n). TOP-UPS first: CLI queue-todo -TopUp -SceneCount S [...] lists products already prepared with fewer than S scenes (their group, scenes, missing): keep their scenes, pick only the missing ones the same way, record them with ALL their scenes in -SceneNames order.
2. Per GROUP of products: Read the group's product sheet ONCE and decide each product's library group (CLI scenes lists the groups: e.g. "Áo" apparel, "Mũ" caps, "Cốc và bình" mugs / bottles, "Thể thao ngoài trời" sports wear, "Nội thất" furniture, "Trang trí nhà cửa" home decor). Then CLI scene-candidates -Group "<library group>" -Limit L with L = S x (products of the group still to do) + 8 (max 60): a random sample of unused photos, numbered contact sheets, candidates[] (n, name). Read EVERY sheet of the sample (one Read each).
3. Pick with a glance, for every product of the group: S DIFFERENT photos that fit it (the garment type / pose / room must make sense for the product: a shirt on a person for a shirt, not a studio shot of a dress), never one photo for two products, spread over the sheet. Nothing fits: CLI scene-candidates ... -Draw 2, then -Draw 3 (another random sample, same flags), then take the best available. A product with no fitting photo after 3 draws is skipped and named in the final report.
4. Record the whole group in ONE call: write a JSON file next to the sheets [{"url":"<link as listed>","group":"<library group>","scenes":["<name>","<name>"]}, ...] and run CLI queue-add-many -File <json> -SceneCount S. The answer lists ok_items[] and errors[] (cause per product): fix only the failed ones (SCENE_REUSED / SCENE_DUPLICATE = another photo from a sheet you already saw; ALREADY_QUEUED = skip) and call again with just those. KEEP GOING until exactly N products are queued or the candidate list is used up: a skipped or ALREADY_QUEUED product is replaced by the next product of the list.
5. Finish: STOP. Tell me in Vietnamese: how many products were queued, the products left out (and why), the errors, how many contact sheets you read.
STOP IF: no products to queue (say so); the library cannot be reached (network) after 1 retry: stop and report. Do NOT retry endlessly; still run step 5.
NEVER: start image creation or press Bắt đầu; write review text, author or rating; open a browser or any web page; edit references.json, urls.txt, products.csv, prepared.csv or any project file by hand (only the CLI writes them); change or delete an entry already in the queue; change `used`; reuse one photo twice for the same product or across products (or pass -AllowReuse); pick a photo you did not see on a sheet; write a script that matches photos to products for you; use background tasks, schedulers or wait tools; run two agents on one browser.
```
