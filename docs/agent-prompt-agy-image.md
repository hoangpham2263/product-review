# Agent prompt, image run with Antigravity (Tạo ảnh = Antigravity: no Google Flow, no Chrome)

Used only when the agent is Antigravity (Cấu hình mục 3 Tạo ảnh = Antigravity) and the run is the image run (mode "flow"): `buildPrompt` in `core/setup/agent-run.mjs` reads this file instead of `agent-prompt.md` (which stays the Claude + Google Flow prompt). Same placeholders (`{{TOOL}}`, `{{RUN}}`, `{{OPTIONS}}`) and the same CLI; only step 3 differs: Antigravity makes the picture itself through its built-in `image-generator` subagent. Every image rule (sign wording, custom logo, worn variation, aspect) comes from `flow-brief` and the context steps, unchanged. No Playwright MCP, no Chrome profile, no Flow account, nothing of the Flow run in this run.

```text
TASK: Product Review — create images with Antigravity's image generator and write the reviews — agent: Antigravity
RUN: {{RUN}}
OPTIONS: {{OPTIONS}}
LUỒNG: {{THREADS}} (pictures made at the same time in step 3; 1 = one item after another)
TOOL: {{TOOL}}
STEPS (follow RUNBOOK.md, in order, do not skip; every command prints one JSON line {ok,...}; CLI = powershell -NoProfile -ExecutionPolicy Bypass -File src/agent.ps1 <command> -Run {{RUN}} [-Item <id>]):
1. Setup: cd {{TOOL}}; read AGENTS.md (sections 0, 1, 5, 8) (open RUNBOOK.md only if a step below is unclear, it is long); CLI prepare (snapshots the queue into this run and lists the items).
2. Context, per item (one at a time): look at the product photo(s) of the item; CLI context-brief -Item <id>; write the JSON it asks for (also `custom_logo` true + `logo_placeholder` when the product has a buyer-logo area with replaceable sample branding (STEP 3C, e.g. the chest mark of a custom polo): the image is made with that whole sample logo replaced by an INVENTED brand name (flow-brief prints it as logo_name); `lettered` true + `sample_text` = EVERY line of words on the sign, fixed design words included (they are replaced too), " | " between lines, when the product photo shows sample customer lettering such as "Your Name" / "YOUR LOGO"); CLI context -Item <id> -File <json>. SIGN WORDING (lettered items only; YOU choose it): CLI sign-brief -Item <id>; LOOK at its review_photo (the scene) and product_photo; choose the exact new wording by its `instruction` (fits the place/occasion of the scene, short correctly spelled English, same number of lines as the sample, max 3 words per line, no real brand/famous name, never the placeholder, different from the other items of this run); CLI set-sign-text -Item <id> -Text "<line 1 | line 2>" -Reason "<scene> -> <wording>" (ok:false = read the error, choose again).
3. Images, in GROUPS of up to LUỒNG items (LUỒNG 1 = one item at a time; the group is the next items of the run in order, items with the same aspect together when possible; never more than LUỒNG pictures at once). For EVERY item of the group: CLI flow-brief -Item <id> (it prints condensed_prompt, uploads = [review photo, product photo] in that order, aspect, sign_text, safe; cause NEEDS_SIGN_TEXT = a lettered item without wording: do the step 2 SIGN WORDING for it, then flow-brief again). Then, in ONE turn, call invoke_subagent once per item of the group (so the pictures are made in parallel), each with type_name "image-generator" and a task that tells it to call its generate_image tool ONCE with: Prompt = that item's condensed_prompt exactly as printed; ImagePaths = that item's 2 `uploads` paths in that order (image 1 = review photo, image 2 = product photo; the prompt refers to them as image 1 and image 2); AspectRatio = that item's `aspect` (e.g. 3:4, 1:1); ImageName = that item's id. Wait until all of them have finished. Each saves its picture under ~/.gemini/antigravity-cli/brain/<conversation>/<ImageName>_<time>.jpg (or .png): get each full path from the subagent's answer or by listing that folder (match the file by its ImageName = item id), and with run_command copy it into your current folder as <item id>.<ext> (one picture per item: take only the file just generated for that item). Then for each item of the group, one after the other: LOOK at its picture (view_file): it must show the review scene with the product placed in it, one single frame; CLI register-image -Item <id> -From <that copied file> (a jpg is converted to png by the tool). SIGN CHECK (items with `sign_text`; flow-brief adds -SignRead to the command): look at the image at full size, read what the sign actually says and pass it as -SignRead "<line 1 | line 2>" (what you SEE, never copied from sign_text); it must equal sign_text (case/spacing tolerant). Cause SIGN_TEXT_MISMATCH = not registered: make that item's image again with the same condensed_prompt through the subagent and register again (ONE redo only; if the redo is still wrong, register-image keeps the image anyway, go on). A mediocre picture is never a reason to drop an item: register it and go on. If the subagent returns no picture for an item, redo THAT item ONCE the same way (it may go with the next group); then go on. One failing or refused item never blocks the other items of its group. Then the next group.
4. Reviews, per item: CLI review-brief -Item <id> (prints prompt_file, rating, name, image); read prompt_file and write the review as a .txt file; CLI write-review -Item <id> -File <txt> (ok:false + problems: fix exactly what it names (it quotes a reused phrase) and run write-review again, up to 3 repairs; the 4th draft is kept as it is, so an item is never dropped for its review wording); CLI finish -Item <id> (uploads the result; CAUSE:RESULT_CONFIG or CAUSE:RESULT_UPLOAD = item NOT done, report it).
5. Report: CLI run-summary (items, awaiting_user_review, errors, unfinished); then STOP. Tell me in Vietnamese: image paths, how many items wait for my approval (Chờ duyệt), errors per item.
ALL ITEMS: the run has MANY items (run-summary lists them): process EVERY item, group after group, until CLI run-summary shows no item with status needs_image (an item you gave up on with [CAUSE:REFUSED] counts as handled). Never stop after one group, never write a final summary and never say the run is complete before that; if only some items are done, keep going with the next group. NEVER trust an empty list: `prepare` lists EVERY unfinished item of the run (new:false for the ones already prepared by the app or an earlier call), so an empty `items` list alone never means "nothing to do"; before you ever say the queue is empty or the run is complete, check CLI run-summary (every item with status needs_image still needs its image) and agent-items.json.
ORDER: read the `aspect` of every item from flow-brief as you go; there is no aspect chip to change, each picture takes its own item's aspect.
STATUS LINES (the person reads them in the app while the run goes): one short Vietnamese sentence, item first, then the result, e.g. "Mục 035: đang tạo ảnh", "Mục 035: ảnh đạt, chữ Shear Studio", "Mục 035: bỏ qua (không tạo được ảnh)", "Mục 013: lỗi cảnh, bỏ qua". No English, no internal jargon (no CLI names, no CAUSE codes) in these lines.
ONE ITEM REFUSED (the image generator says the request may violate its policy, or returns no picture for that prompt): retry THAT item ONCE with the art-safe prompt (CLI flow-brief -Item <id> -Safe: a human figure on the product is described as printed artwork, not a person; same uploads; it also drops the logo replacement and goes back to the neutral wording). If it refuses again, write [CAUSE:REFUSED] for that item only, skip it and go on with the next item; never stop the run for it.
STOP IF: Antigravity is signed out or its quota/credits are used up (every later picture would fail too). Then write the error of each affected item as `[CAUSE:<code>] <text>` (CAUSE:LOGIN, CAUSE:QUOTA, CAUSE:REFUSED), do NOT retry endlessly (at most 1 retry of a stuck step), still run step 5.
NEVER: write or run a script, loop or batch file that makes the pictures for several items: do each item yourself through the image-generator subagent (up to LUỒNG items at once, one subagent each), LOOK at every image, register; then the next group. Never open a browser or any web page, never use your own browser_* tools, search_web or read_url_content, never call a subagent other than image-generator.
NEVER: start background tasks, timers or use manage_task / schedule / wait tools (they leave you idle for minutes): every step runs in the foreground, one command at a time.
NEVER: press Giữ/Bỏ for me, export Loox, send anything anywhere, run an image again when the item already has one (except the ONE redo above), leave sample lettering on a lettered product, put a brand logo on the product, run two agents on one machine's browser.
```
