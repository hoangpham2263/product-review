# Prep prompt (Claude Code picks the scene photos of a project's products IN ADVANCE and stores them, so "Thêm vào hàng chờ" is instant)

The only source of this prompt: the app ("Chuẩn bị trước" in the Dự án popup) and `buildPrompt({ mode: "prep" })` in `core/setup/agent-run.mjs` read the `text` block below. Placeholders: `{{TOOL}}` = this tool's folder, `{{RUN}}` = the run id, `{{PROJECT}}` = the project id (folder under `workspace/projects/`), `{{OPTIONS}}` = this run's options (category, only-unused, how many products, scenes per product). Same fixed template as `docs/queue-prompt.md`, `docs/agent-prompt.md`, `docs/scan-prompt.md` and `docs/reviews-count-prompt.md`: TASK, OPTIONS, TOOL, STEPS (numbered, 1:1 with the "Chuẩn bị trước" part of the "Dự án" section of RUNBOOK.md), STOP IF, NEVER.

It runs on the LIGHT runner (own state `workspace/runs/prep-run.*`, no browser, no Playwright MCP, no Chrome profile), so it can run while Bắt đầu runs. It writes ONLY `workspace/projects/<id>/prepared.csv` (one row per product the moment its scenes are picked); it never touches the queue (`urls.txt`, `references.json`). Claude chooses the scenes itself (no matching code); `src/scan.ps1 prep-status | prep-todo | scenes | scene-get | prep-add` only list, download, verify (md5 / sha256, perceptual hash) and write the row.

```text
TASK: Product Review — prepare in advance the scene photos of the products of a project (S scenes per product, from OPTIONS; store them in prepared.csv, do not touch the queue, do not create images) — agent: Claude Code
RUN: {{RUN}}
PROJECT: {{PROJECT}}
OPTIONS: {{OPTIONS}}
TOOL: {{TOOL}}
STEPS (follow RUNBOOK.md "Dự án" > "Chuẩn bị trước", in order, do not skip; every command prints one JSON line {ok,...}; CLI = powershell -NoProfile -ExecutionPolicy Bypass -File src/scan.ps1 <command> -Project {{PROJECT}} ...):
1. Setup: cd {{TOOL}}; read AGENTS.md (sections 0, 5 and "Dự án") + RUNBOOK.md "Dự án". OPTIONS gives the category (empty = all), only-unused (T/F), how many products to prepare (all = until none is left) and "scenes per product" (S, 1-4). CLI prep-status [-Collection "<category>"] [-UnusedOnly] (counts), then CLI prep-todo [-Collection "<category>"] [-UnusedOnly] -Limit 30 (url, title, collection, image = the project's product photo): products not queued and not prepared yet, in order. After every 30 prepared, call prep-todo again: the rows you stored are no longer listed. Nothing to do = go to step 5.
2. Library: CLI scenes (the groups), then CLI scenes -Group "<group>" -Category <category> -Prefetch -Limit 30 (its photos with name, category, used_count, dup_of, checked; used_count also counts scenes already prepared for other products; -Prefetch downloads the category so every photo can be compared; the list is already ordered: not used first, copies last, shuffled, so do NOT just take the first ones). Groups: "Áo" for apparel (shirts, polos, tees, hoodies, jackets), "Thể thao ngoài trời" for jerseys, fishing, running, cycling, outdoor sports wear, "Nội thất" for furniture. A photo is on disk when `local` is set; otherwise CLI scene-get -Group "<group>" -SceneNames "<name>" downloads it and prints its path. You LOOK at photos with the Read tool (the product photo, the scene photos).
3. Per product, one at a time: Read the product photo FIRST and decide what it is (type, how it is worn or used). Choose the right group for that type, look at candidate scene photos (scene-get, then Read) and pick S DIFFERENT scenes that fit the product: the person / room must make sense for it. Never the same scene twice for one product (two different photos, not the same picture under two names), and NEVER reuse a scene across products: skip photos with dup_of set or used_count > 0 (the CLI rejects them anyway: SCENE_DUPLICATE, SCENE_REUSED). Look at at least 6 candidates per product and spread the picks across the category. If you cannot find S scenes that really fit, do NOT force a bad one: note the product with prep-add -Skip and GO ON.
4. Store it NOW (one product, one call, right after you picked): CLI prep-add -Url <the link exactly as listed> -Group "<group>" -SceneNames "<a>,<b>,..." -SceneCount S (exactly S names). No fitting scenes: CLI prep-add -Url <link> -Skip -Reason "no-fit: <short reason>". A failed call: read the error, fix your choice or retry ONCE; ALREADY_PREPARED / ALREADY_QUEUED = skip that product and say so; SCENE_DUPLICATE / SCENE_REUSED = pick other scenes (never add -AllowReuse on your own). KEEP WORKING until the products are all prepared (or the number in OPTIONS is reached, or prep-todo is empty). This run ends the moment you write a message without a tool call, so write NO progress message, NO partial report and NO question before the end; the only message you write is the step 5 report.
5. Finish: CLI prep-status, then STOP. Tell me in Vietnamese: how many products were prepared (ready) and how many skipped (no fit, with the reason in one line each), the errors, and the prep-status numbers (ready / products / still to prepare).
STOP IF: no products to prepare (say so); the library cannot be reached (network) after 1 retry: stop and report; a scene or product photo that cannot be read. Do NOT retry endlessly (at most 1 retry of a stuck step); still run step 5.
NEVER: put anything into the queue (queue-add, queue-direct, queue-from-prepared) or edit urls.txt, references.json, prepared.csv, products.csv or any project file by hand (only the CLI writes them); start image creation or press Bắt đầu; write any review text, author or rating; open a browser or any web page; change `used`; reuse one scene photo twice for the same product or across products (or pass -AllowReuse); pick a scene that does not fit the product just to finish; write a script that matches scenes to products for you.
```
