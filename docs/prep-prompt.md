# Prep prompt (Claude Code picks the scene photos of a project's products IN ADVANCE and stores them, so "Thêm vào hàng chờ" is instant)

The only source of this prompt: the app ("Chuẩn bị trước" in the Dự án popup, option "Bốc ngẫu nhiên, không AI" off) and `buildPrompt({ mode: "prep" })` in `core/setup/agent-run.mjs` read the `text` block below. Placeholders: `{{TOOL}}` = this tool's folder, `{{RUN}}` = the run id, `{{PROJECT}}` = the project id, `{{OPTIONS}}` = this run's options (category, only-unused, how many products, scenes per product). Same fixed template as `docs/queue-prompt.md`.

It runs on the LIGHT runner (own state `workspace/runs/prep-run.*`, no browser, no Chrome profile), so it can run while Bắt đầu runs. It writes ONLY `workspace/projects/<id>/prepared.csv` and the used-scene ledger; it never touches the queue (`urls.txt`, `references.json`). The code draws a random sample of unused photos from the product's library group (`scene-candidates`) and tiles it into numbered contact sheets; Claude looks at the sheet and picks the scenes that fit; `prep-add-many` records all picks of a batch with one call.

```text
TASK: Product Review — prepare in advance the scene photos of the products of a project (S scenes per product, from OPTIONS; store them in prepared.csv, do not touch the queue, do not create images) — agent: Claude Code
RUN: {{RUN}}
PROJECT: {{PROJECT}}
OPTIONS: {{OPTIONS}}
TOOL: {{TOOL}}
SHARD (only when OPTIONS contains "shard file:" / "shard:"; otherwise ignore this line): other runs prepare the same project at the same time, each on its OWN slice. Add `-OnlyFile <that shard file>` to EVERY prep-todo call and prepare ONLY products prep-todo lists.
STEPS (every command prints one JSON line {ok,...}; CLI = powershell -NoProfile -ExecutionPolicy Bypass -File src/scan.ps1 <command> -Project {{PROJECT}} ...). FAST: batch commands in one shell call, look at photos only on numbered CONTACT SHEETS (one Read = up to 20 photos), never one file at a time, never wait or schedule anything:
1. Setup: cd {{TOOL}}; read AGENTS.md (sections 0, 5 and "Dự án"). OPTIONS gives the category (empty = all), only-unused (T/F), how many products (all = until none is left), S (scenes per product, 1-4) and whether to retry skipped products. CLI prep-status [-Collection "<category>"] [-UnusedOnly], then CLI prep-todo -Grouped -Sheet [-Collection "<category>"] [-UnusedOnly] [-RetrySkipped when OPTIONS says so] -Limit 40: the products not queued and not prepared yet, grouped by kind (groups[]: key, products with n / url / title / image, sheet = ONE contact sheet of the group's product photos numbered like n). When the list is empty, go to step 5.
2. Per GROUP of products: Read the group's product sheet ONCE and decide each product's library group (CLI scenes lists the groups: e.g. "Áo" apparel, "Mũ" caps, "Cốc và bình" mugs / bottles, "Thể thao ngoài trời" sports wear, "Nội thất" furniture, "Trang trí nhà cửa" home decor). Then CLI scene-candidates -Group "<library group>" -Limit L with L = S x (products of the group) + 8 (max 60): a random sample of unused photos, numbered contact sheets, candidates[] (n, name). Read EVERY sheet of the sample (one Read each).
3. Pick with a glance, for every product of the group: S DIFFERENT photos that fit it (garment type / pose / room must make sense for the product), never one photo for two products, spread over the sheet. Nothing fits: CLI scene-candidates ... -Draw 2, then -Draw 3 (another random sample), then take the best available; a product with no fitting photo after 3 draws is recorded as skipped.
4. Record the whole group in ONE call: write a JSON file [{"url":"<link as listed>","group":"<library group>","scenes":["<name>","<name>"]}, {"url":"<link>","skip":true,"reason":"<short reason>"}, ...] and run CLI prep-add-many -File <json> -SceneCount S. The answer lists ok_items[] and errors[] (cause per product): fix only the failed ones (SCENE_REUSED / SCENE_DUPLICATE = another photo from a sheet you already saw; ALREADY_QUEUED = skip) and call again with just those. Then the next group.
5. Finish: CLI prep-status, then STOP. Tell me in Vietnamese: how many products were prepared (ready) and skipped (with the reason in one line each), the errors, the prep-status numbers (ready / products / still to prepare) and how many contact sheets you read.
STOP IF: no products to prepare (say so); the library cannot be reached (network) after 1 retry: stop and report. Do NOT retry endlessly; still run step 5.
NEVER: put anything into the queue (queue-add, queue-add-many, queue-direct, queue-from-prepared) or edit urls.txt, references.json, prepared.csv, products.csv or any project file by hand (only the CLI writes them); start image creation or press Bắt đầu; write review text, author or rating; open a browser or any web page; change `used`; reuse one photo twice for the same product or across products (or pass -AllowReuse); pick a photo you did not see on a sheet; write a script that matches photos to products for you; use background tasks, schedulers or wait tools.
```
