# Prep prompt (Claude Code picks the scene photos of a project's products IN ADVANCE and stores them, so "Thêm vào hàng chờ" is instant)

The only source of this prompt: the app ("Chuẩn bị trước" in the Dự án popup) and `buildPrompt({ mode: "prep" })` in `core/setup/agent-run.mjs` read the `text` block below. Placeholders: `{{TOOL}}` = this tool's folder, `{{RUN}}` = the run id, `{{PROJECT}}` = the project id (folder under `workspace/projects/`), `{{OPTIONS}}` = this run's options (category, only-unused, how many products, scenes per product). Same fixed template as `docs/queue-prompt.md`, `docs/index-prompt.md`, `docs/agent-prompt.md`, `docs/scan-prompt.md` and `docs/reviews-count-prompt.md`: TASK, OPTIONS, TOOL, STEPS (numbered, 1:1 with the "Chuẩn bị trước" part of the "Dự án" section of RUNBOOK.md), STOP IF, NEVER.

It runs on the LIGHT runner (own state `workspace/runs/prep-run.*`, no browser, no Playwright MCP, no Chrome profile), so it can run while Bắt đầu runs. It writes ONLY `workspace/projects/<id>/prepared.csv` (one row per product the moment its scenes are picked) and, when the library group it needs is not tagged yet, the shared tag index `workspace/source-photos/scene-index.json`; it never touches the queue (`urls.txt`, `references.json`). Claude chooses the scenes itself (no matching code); `src/scan.ps1 prep-status | prep-todo -Grouped -Sheet | scene-index-status | scene-index-todo | scene-index-add | scene-candidates | contact-sheet | scenes | scene-get | prep-add` only list, tile photos into numbered contact sheets, rank indexed scenes by their tags, download, verify (md5 / sha256, perceptual hash) and write the row.

Speed (2026-11-21): a run on dreamyvows-com took 9+ minutes and 60+ turns before its first saved product, because Claude opened every candidate scene file with Read (6+ per product). Now Claude reads ONE product sheet per group of products and ONE candidate sheet per 20 scenes, and the candidates are only the unused, non-duplicate scenes whose tags match the product type.

```text
TASK: Product Review — prepare in advance the scene photos of the products of a project (S scenes per product, from OPTIONS; store them in prepared.csv, do not touch the queue, do not create images) — agent: Claude Code
RUN: {{RUN}}
PROJECT: {{PROJECT}}
OPTIONS: {{OPTIONS}}
TOOL: {{TOOL}}
STEPS (follow RUNBOOK.md "Dự án" > "Chuẩn bị trước", in order, do not skip; every command prints one JSON line {ok,...}; CLI = powershell -NoProfile -ExecutionPolicy Bypass -File src/scan.ps1 <command> -Project {{PROJECT}} ...). SPEED: you look at photos on numbered CONTACT SHEETS (one Read = up to 20 photos), never one scene file at a time:
1. Setup: cd {{TOOL}}; read AGENTS.md (sections 0, 5 and "Dự án") + RUNBOOK.md "Dự án". OPTIONS gives the category (empty = all), only-unused (T/F), how many products to prepare (all = until none is left) and "scenes per product" (S, 1-4). CLI prep-status [-Collection "<category>"] [-UnusedOnly] (counts), then CLI prep-todo -Grouped -Sheet [-Collection "<category>"] [-UnusedOnly] [-RetrySkipped when OPTIONS says retry skipped (no-fit) products: T] -Limit 40: the products not queued and not prepared yet, GROUPED by kind (groups[]: key = collection or title type word, products with n / url / title / image, sheet = ONE contact sheet of the group's product photos numbered like n). When those groups are done call prep-todo again: stored rows are no longer listed. Nothing to do = go to step 5.
2. Library index: CLI scene-index-status (photos / indexed per library group). Scenes are chosen from the tag index. If the library group you need has untagged photos (indexed < photos), tag them first exactly like RUNBOOK "Gắn nhãn kho ảnh": scene-index-todo -Group "<group>" -Limit 20 (prints a numbered sheet) -> Read the sheet ONCE -> write the tags JSON next to it -> scene-index-add -File <json>; repeat until count is 0. Groups: "Áo" apparel (shirts, polos, tees, hoodies, jackets), "Thể thao ngoài trời" jerseys / fishing / running / cycling / outdoor sports wear, "Nội thất" furniture, "Trang trí nhà cửa" home decor (wall signs, neon signs, wall art); CLI scenes lists every group.
3. Per GROUP of products (not per product): Read the group's product sheet ONCE and decide the product type (e.g. "neon wall sign", "polo shirt", "coffee table"). A product on the sheet that is clearly another kind: Read its own photo and treat it alone. Then CLI scene-candidates -Group "<library group>" -Fits "<product type>" [-Setting "<a>,<b>" when only some places make sense] -Limit L with L = S x (products of the group) + 8 (max 60): unused, non-duplicate indexed scenes ranked by tag match, with numbered sheets (20 per sheet, numbers continue) and candidates[] (n, name, setting, fits, note). Read EVERY sheet of the list (one Read each) and judge the fit yourself: the room / person must make sense for the product (a neon sign on a clear wall, a shirt worn by a person outdoors, not a studio shot of a dress). Tags only narrow the list: never pick a scene you have not seen on a sheet. Assign S DIFFERENT fitting scenes to each product of the group, spread across the sheet (different rooms), never one scene for two products (the CLI rejects SCENE_DUPLICATE / SCENE_REUSED anyway). The S scenes of one product all come from ONE library group. matched:false or too few fitting scenes = the remaining products of the group are no-fit (step 4 -Skip), never a forced bad pick.
4. Store as you go (one product, one call, right after you assigned it, so Thêm vào hàng chờ can use it at once): CLI prep-add -Url <the link exactly as listed> -Group "<group>" -SceneNames "<a>,<b>,..." -SceneCount S (exactly S names from the legend). No fitting scenes: CLI prep-add -Url <link> -Skip -Reason "no-fit: <short reason>". With retry skipped: T, a product skipped before is listed again: a new pick REPLACES its skipped row, a new -Skip refreshes it (ready / consumed rows are never touched). A failed call: read the error, fix your choice or retry ONCE; ALREADY_PREPARED / ALREADY_QUEUED = skip that product and say so; SCENE_DUPLICATE / SCENE_REUSED = take another scene from a sheet you already looked at (never add -AllowReuse on your own); sheets used up = scene-candidates again (it leaves out the scenes now used). KEEP WORKING until the products are all prepared (or the number in OPTIONS is reached, or prep-todo is empty). This run ends the moment you write a message without a tool call, so write NO progress message, NO partial report and NO question before the end; the only message you write is the step 5 report.
5. Finish: CLI prep-status, then STOP. Tell me in Vietnamese: how many products were prepared (ready) and how many skipped (no fit, with the reason in one line each), the errors, the prep-status numbers (ready / products / still to prepare) and how many contact sheets you read.
STOP IF: no products to prepare (say so); the library cannot be reached (network) after 1 retry: stop and report; a scene or product photo that cannot be read. Do NOT retry endlessly (at most 1 retry of a stuck step); still run step 5.
NEVER: put anything into the queue (queue-add, queue-direct, queue-from-prepared) or edit urls.txt, references.json, prepared.csv, scene-index.json, products.csv or any project file by hand (only the CLI writes them); start image creation or press Bắt đầu; write any review text, author or rating; open a browser or any web page; change `used`; reuse one scene photo twice for the same product or across products (or pass -AllowReuse); pick a scene that does not fit the product just to finish, or one you know only from its tags; write a script that matches scenes to products for you.
```
